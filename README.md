# Makeflow CRM

نظام إدارة العملاء الداخلي لشركة Makeflow — عربي فصيح بالكامل، من اليمين إلى اليسار، لثلاثة مستخدمين.

الواجهة عربية فصحى. الكود وقاعدة البيانات وأسماء المتغيّرات بالإنجليزية.

---

## شغّله بدقيقة

```bash
npm install
npm run dev
```

افتح <http://localhost:3000> — يعمل فوراً **ببيانات تجريبية** دون أي إعداد،
لتتمكّن من معاينة التصميم قبل ربط قاعدة البيانات. يظهر شريط بنفسجي في الأعلى
يذكّرك بأنك في وضع المعاينة.

## اربطه بقاعدة بياناتك

انسخ `.env.example` إلى `.env.local` واملأ المفتاحين:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
```

بمجرّد توفّر المفتاحين، تتوقّف البيانات التجريبية ويقرأ التطبيق من Supabase.
وإن فشل الاتصال، يعود إلى البيانات التجريبية بدل أن تنكسر الشاشة، ويسجّل السبب
في سجلّ الخادم.

### متغيّرات البيئة

| المتغيّر | موضعه | وظيفته |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | الواجهة و Vercel | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | الواجهة و Vercel | المفتاح العام — تحكمه سياسات RLS |
| `SUPABASE_SERVICE_ROLE_KEY` | **n8n فقط** | يتجاوز كل سياسات الحماية |

> ⚠️ لا يوضع مفتاح service role إطلاقاً في الواجهة ولا في Vercel ولا في أي
> متغيّر يبدأ بـ `NEXT_PUBLIC_`. فهو يتجاوز RLS بالكامل، ومكانه n8n وحده.

## قاعدة البيانات

شغّل الملفات بهذا الترتيب على مشروع Supabase (من SQL Editor أو `psql`):

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/migrations/0001_init.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/migrations/0002_seed.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/functions/upsert_lead.sql
```

> ⚠️ قبل تشغيل `0002_seed.sql`: غيّر كلمة المرور المؤقتة
> `Makeflow#Change-Me-2026` داخل الملف، ثم غيّرها مرة أخرى بعد أول دخول.

| الملف | محتواه |
|---|---|
| `0001_init.sql` | 9 أنواع · 14 جدولاً · فهارس · مشغّلات · 5 عروض · سياسات RLS |
| `0002_seed.sql` | 3 موظفين · 7 منتجات · مساران بـ 13 مرحلة · 5 وسوم |
| `upsert_lead.sql` | نقطة الدخول الوحيدة لـ n8n |

### القواعد المحمية في قاعدة البيانات

1. تغيير المرحلة يصفّر عدّاد «متوقفة منذ».
2. مرحلة الربح تُغلق الصفقة بحالة `won`.
3. مرحلة الخسارة **ترفض الحفظ** دون `lost_reason` — النافذة في الواجهة، والحماية في قاعدة البيانات.
4. كل صفقة جديدة تُنشئ مهمة «أول تواصل» خلال 24 ساعة.
5. الدفعات المؤكَّدة متى غطّت قيمة الصفقة نقلتها تلقائياً إلى مرحلة الدفع (إلى الأمام فقط).

## n8n

### مثال استدعاء

```bash
curl -X POST "$SUPABASE_URL/rest/v1/rpc/upsert_lead" \
  -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" \
  -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "p_phone": "0599123456",
    "p_full_name": "أحمد صالح",
    "p_product_name": "دورة الأتمتة بالذكاء الاصطناعي (n8n)",
    "p_source": "whatsapp_bot",
    "p_summary": "تواصل عبر البوت واستفسر عن سعر الدورة",
    "p_payment_status": "needs_checking",
    "p_org_name": null,
    "p_amount": 250,
    "p_external_ref": "waha-msg-001"
  }'
```

الرد:

```json
{
  "contact_id": "…",
  "deal_id": "…",
  "organization_id": null,
  "contact_created": true,
  "deal_created": true
}
```

### لماذا تكرار الاستدعاء آمن

الدالة **مضمونة التكرار (idempotent) على (رقم الهاتف + المنتج)**: نادِها عشر
مرات بالبيانات نفسها فتعيد المعرّفات ذاتها دون أي تكرار. يُوحَّد الرقم إلى صيغة
E.164 قبل المقارنة، فـ `0599123456` و `+970599123456` و `0599 123-456` كلها
الشخص نفسه. ويمنع `p_external_ref` تكرار النشاط عند إعادة محاولة n8n.

الحقل الإلزامي الوحيد: `p_phone`، وما عداه اختياري.

## النشر على Vercel

1. ادخل [vercel.com](https://vercel.com) وسجّل بحساب GitHub.
2. اختر `Add New → Project` ثم مستودع `MakeFlow-CRM`.
3. أضف `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
4. اضغط `Deploy` لتحصل على رابط يعمل على الهاتف والحاسوب.

### اللغة والطباعة

الواجهة بالعربية الفصحى. الخط الأساسي **IBM Plex Sans Arabic** ويحمَّل معه
**Tajawal** خطاً احتياطياً فعلياً عبر `next/font`. ضُبطت الطباعة للعربية
تحديداً: قياس أساسي أكبر، ومسافة سطر أوسع (1.75)، وتباعد حروف صفر — لأن
تباعد الحروف يكسر اتصال الحرف العربي — مع منع اصطناع الأوزان.

الأرقام لاتينية دائماً (1234)، وتُعزل داخل النص العربي بصنف `.num` حتى لا
ينتقل الرمز «+» إلى آخر الرقم.

### نظام التلميحات (ثلاث طبقات)

المستخدمون يتعاملون مع نظام CRM لأول مرة، لذا تشرح الواجهة نفسها أثناء الاستعمال:

1. **سطر تحت كل عنوان** — يشرح الشاشة بلغة بسيطة، وظاهر دائماً.
2. **أيقونة ⓘ** — تعريف ومثال ملموس، تُفتح بالمرور أو بالنقر.
3. **شاشات فارغة تُعلِّم** — لا وجود لعبارة «لا توجد بيانات»؛ شرح وزر إجراء.

جميع النصوص في `lib/hints.ts`، ولغتها عربية فصحى.

### استيراد جهات الاتصال من Excel

من شاشة **جهات الاتصال ← استورد من Excel** (المسار `/contacts/import`):

1. **نزّل القالب** — ملف `.xlsx` يُولَّد في المتصفح، بترويسة ملوّنة تميّز الأعمدة
   الإلزامية، وصف شرح لكل عمود، وصف مثال.
2. **املأ البيانات** — صف لكل شخص. الاسم ورقم الهاتف إلزاميان فقط.
3. **ارفع الملف** — يُفحص كل صف ويُصنَّف قبل الحفظ: جاهز، أو يحتاج تصحيحاً،
   أو مكرّر داخل الملف، أو مسجَّل مسبقاً في النظام. لا يُحفظ شيء قبل موافقتك.

| العمود | إلزامي | ملاحظات |
|---|:---:|---|
| الاسم الكامل | ✓ | |
| رقم الهاتف | ✓ | أي صيغة معتادة؛ تُوحَّد تلقائياً إلى E.164 |
| البريد الإلكتروني | | |
| المدينة | | |
| الجهة | | تُنشأ الجهة تلقائياً إن لم تكن موجودة |
| الدور في الجهة | | |
| المصدر | | بوت واتساب، إعلان فيسبوك، توصية، ورشة، إدخال يدوي |
| ملاحظات | | |

تُطابَق الأعمدة بأسمائها لا بترتيبها، فإعادة ترتيبها لا تكسر الاستيراد. تُقبل
صيغة `.csv` أيضاً، بحد أقصى 5 ميغابايت.
